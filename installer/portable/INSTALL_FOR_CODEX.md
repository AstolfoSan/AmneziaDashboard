# Развёртывание AmneziaDashboard для Codex

## 1. Уточнить цель и провести read-only аудит

Получить у человека реальные адреса и доступ, режим `direct`/`cascade`, сервер
панели, VPN-вход, ожидаемый зарубежный выход, HTTPS-имя/IP и свободный порт панели.
Нельзя использовать адреса из примеров как реальные цели. По умолчанию никакие
изменения на исходных серверах этой панели не разрешены.

Проверить Linux/архитектуру, Docker/Compose, Python/venv, RAM/диск, существующие
слушатели и подсети Docker/VPN. Примеры предполагают Linux и публичный IPv4/DNS
для VPN; IPv6 endpoint в этой версии не поддержан. Панель с валидным TLS может
работать на нестандартном TCP-порту, например 10443, не занимая VPN TCP 443.

Проверить совместимый AmneziaWG **3.1**, контейнер, имя интерфейса, внутренние
пути `awg0.conf`/`clientsTable`, сохранение клиентского PSK/AllowedIPs при `awg set`,
публичный UDP-порт и фактический интернет-выход. Не печатать полные конфиги/ключи.
Если VPN ещё не установлен, остановиться и согласовать его отдельную установку
официальным способом. Этот комплект не устанавливает маршрутизацию или VPN-движок.

Сделать секретный бэкап существующих настроек/клиентов и проверку хеша. Записать
PID/время старта и хеши рабочих VPN-конфигураций для последующей сверки.

## 2. Сформировать настройки, не меняя сервер

Изменить копию `examples/direct.json` или `examples/cascade.json`:

- `public_origin`: внешний корневой HTTPS URL панели, без пути/пароля.
- `panel_bind_ip`: адрес привязки на сервере панели. `0.0.0.0` означает внешнюю
  публикацию выбранного TLS-порта; это должно соответствовать согласованной цели.
- `publish_http_challenge`: по умолчанию false. Не включать TCP 80, если он занят;
  использовать существующий HTTP frontend/DNS challenge для сертификата.
- `panel_network_cidr`: не пересекающаяся с VPN/другими сетями private /24–/28.
  Приложение получает адрес сети +2, nginx +3.
- `route_label`/`route_path`: понятные надписи. Они не меняют реальные маршруты.
- `agent.same_host`: true, если агент на физическом сервере панели. Тогда SSH
  идёт к `host.docker.internal` через Docker host-gateway, а не к loopback контейнера.
- Для удалённого агента: `ssh_host`, `ssh_port` и точный внешний IPv4 `/32`
  сервера панели в `source_cidr`. Проверить фактически наблюдаемый source IP.
- `vpn.public_host`: адрес **клиентского VPN-входа**. В direct это зарубежный VPS,
  в cascade — входной VPS, не выходной. `endpoint_port` при необходимости задаёт
  внешний NAT-порт; иначе используется ListenPort интерфейса.
- `vpn.container`, `interface`, `config_path`, `clients_table`, `awg_binary`
  (по умолчанию `awg` внутри контейнера), `mtu`, `dns1`, `dns2`.
- `vpn.state_dir`: отдельная новая папка состояния агента, по умолчанию
  `/var/lib/amnezia-dashboard-agent`.
- `images`: официальные Python/nginx с проверенным digest и архитектурой.

`mode=direct` не содержит зависимости от RU. `mode=cascade` требует уже рабочего
каскада с проверенным fail-closed поведением. Панель только выдаёт профили к входу.

```text
python configure.py --config examples/my-deployment.json --output deployment-new
```

Выходная папка должна быть новой. Генератор не вызывает SSH, Docker или systemctl.
`compose.yaml` имеет формат JSON, который является допустимым YAML для Compose.
Не переносить сам portable-kit из оригинального рабочего проекта на сервер;
переносится только сгенерированная deployment-папка.

## 3. Подготовить агент на VPN-входе

Не перезаписывать существующие `/opt/amnezia-dashboard-agent`,
`/etc/amnezia-dashboard` или state_dir. Если они есть — выяснить происхождение
и согласовать обновление вместо новой установки.

На VPN-входе разместить из deployment-папки:

1. `agent/agent.py` и `agent/portable_settings.py` в `/opt/amnezia-dashboard-agent/`.
2. Создать venv `/opt/amnezia-dashboard-agent/venv` и установить **agent/requirements.txt**.
   Это только cryptography и её зависимости, не вся веб-панель.
3. `agent.json` в `/etc/amnezia-dashboard/agent.json`, root:root, режим 0600;
   code/config не должны быть доступны на запись посторонним.
4. Создать state_dir root:root 0700. Не копировать туда чужие `.enc` или master.key.
5. Установить сгенерированные `amnezia-dashboard-expiry.service`/`.timer`
   в `/etc/systemd/system/`, проверить `systemd-analyze verify`. Пока не запускать
   службы против неинвентаризированного VPN.

Ключи для новых клиентов генерирует `awg` **внутри указанного контейнера**;
бинарник на хосте `/usr/local/bin/awg-v3.1` не нужен.
Docker-имя контейнера на сервере может быть своим; экспорт `.vpn` при этом
сохраняет проверенный клиентский тип `amnezia-awg2` и `protocol_version=3.1`, а не
подставляет произвольное имя контейнера в клиентский формат. Разделение учитывает
[типизированную модель контейнеров Amnezia](https://github.com/amnezia-vpn/amnezia-client/blob/dev/client/core/controllers/selfhosted/installController.cpp).
Состояние агента привязывается к public_host/порту/контейнеру/интерфейсу/путям.
Попытка молча направить старое состояние на другой VPN будет отвергнута.
Не удалять deployment-binding.json ради обхода этой защиты.

## 4. Ограниченный SSH-транспорт

Создать новый ed25519 ключ только для панели. Секретную половину положить в
`deployment/secrets/agent_key` на сервере панели; существующие личные SSH-ключи
веб-контейнеру не передавать. Папка secrets — 0700, ключ — 0400, владелец UID 10001.

В authorized_keys root **добавить**, сохраняя остальные строки, только новый
публичный ключ в формате `authorized-key.example`. Заменить `<NEW-PUBLIC-KEY>`
полной публичной частью `ssh-ed25519 …`, не приватным ключом.
Шаблон содержит `from="точный IPv4/32"`, `restrict` и единственную forced-command
операцию агента. Окружение forced-command очищается, Python игнорирует
PYTHONPATH/user-site, Docker закреплён за локальным unix socket.
Для same_host источник — адрес приложения сети Docker +2;
для remote — внешний адрес панели после NAT. Уточнить реальные source IP и
firewall-правила: не заменять from на `*` и не открывать SSH всему интернету.
Проверить sshd -t; обычные администраторские ключи должны продолжать работать.

В `secrets/agent_known_hosts` записать **предварительно проверенный** host key
VPN-сервера для точного имени `agent.ssh_host`; для нестандартного порта —
`[hostname]:port`. Для same_host это имя `host.docker.internal`, ключ всё равно
должен совпадать с ключом самого хоста, сверенным по доверенному SSH/консоли.
Один ssh-keyscan без независимой сверки fingerprint недостаточен. Файл 0400,
UID 10001. Не использовать StrictHostKeyChecking=no и не включать SSH-agent forwarding.

## 5. Веб-часть, TLS и автопродление

Разместить deployment-папку в **новой** `/opt/amnezia-dashboard` на сервере панели.
Оставить отдельные app/data/secrets/certs. data — 0700 с UID/GID 10001:10001.
Веб-контейнер не получает Docker socket, host network или права администратора.

До запуска получить доверенный сертификат для public_origin. Файлы:
`certs/fullchain.pem`, `certs/key.pem`; nginx работает как UID/GID 101:101,
ключ должен читаться только этим UID, не быть общедоступным. Проверить имя/IP SAN,
срок, цепочку и соответствие приватного ключа сертификату.

Настроить автоматическое продление выбранным официальным ACME-клиентом. В deploy-hook:
сначала проверить новую пару/имя/срок, затем атомарно обновить эти два файла,
проверить `docker compose exec -T web nginx -t` и плавно перезагрузить **только**
nginx панели (`docker compose exec -T web nginx -s reload`). Не останавливать
VPN/общий nginx для standalone HTTP-01. Не публиковать challenge-порт без проверки
конфликтов. Успешный renewal dry-run с deploy-hook обязателен до завершения.
Этот архив не содержит сертификатов и не настраивает ACME автоматически.

## 6. Запуск и проверки

После подтверждения настроек и новых ограниченных доступов:

```text
docker compose config -q
docker compose build app
docker compose up -d
systemctl daemon-reload
systemctl enable --now amnezia-dashboard-expiry.timer
```

Последние команды systemctl выполняются на **VPN-входе**, а Compose — на сервере
панели. Проверить первый успешный запуск expiry.service и повторные циклы таймера.
Проверить /healthz внутри app, контейнеры, отсутствие sync_error и свежий last_sync.
Внешний `/admin` должен открываться с валидным TLS без curl -k/исключений браузера.
`/api/dashboard` без входа должен возвращать 401.

Первый владелец — `owner`. Bootstrap-пароль создан в data/bootstrap-password.txt;
передавать его человеку приватно, не в логах/чате. Смену пароля через браузер
передать человеку согласно правилам подтверждения. Не создавать заранее известный
пароль из примеров или тестов.

Создать отдельную тестовую группу/устройство с новыми ключами. Проверить реальную
выдачу `.vpn`, импорт на устройстве, HTTPS-трафик и ожидаемый зарубежный выход.
В direct трафик не должен идти через RU; в cascade подтвердить именно нужный exit
и сохранность fail-closed. Проверить паузу, срок, квоту и восстановление с тем же
конфигом, не сбрасывая счётчики. Тестовый клиент после теста отозвать; настоящих
клиентов для тестов не использовать. Указать, если физический мобильный импорт
или реальный egress проверить не удалось. Локальные unit-тесты этого не заменяют.

Сверить старые VPN PID/конфиги/клиентов с бэкапом. Плановый VPN-трафик не должен
прерываться из-за установки панели. Сделать отдельный секретный итоговый бэкап.

## 7. Сохранность, обновления и ограничения

Согласованно сохранять panel data/panel.sqlite3 + data/master.key, весь state_dir
агента с master.key/метрами/привязкой и конфигурацию/clientsTable самого VPN.
Потеря одного master.key не восстанавливается публичным ZIP. Для переноса уже
выданных клиентов требуется отдельный план миграции VPN endpoint/ключей/БД.

Не откатывать старый worker после назначения квот: он может перестать их
проверять. Не откатывать код управления администраторами без фильтра deleted_at.
Нельзя восстанавливать старую БД поверх новых клиентов, пауз/сроков и счётчиков.
История графиков ограничена 24 часами минутных данных и 31 завершённым днём плюс
текущий день; lifetime-счётчики клиентов не удаляются этой очисткой.

Квоты и сроки проверяются раз в 15 секунд: это не точный пакетный hard cap.
Данные между опросами могут превысить лимит, неснятые до аварии байты нельзя
реконструировать. Официальный мобильный клиент может показывать не все выданные
панелью записи в собственном GUI; агент хранит отдельную защищённую базу.

Один экземпляр = один вход. Не направлять несколько независимых worker-state
на один и тот же VPN-интерфейс: у них не будет общего allocation/lock. Не менять
пиры одновременно сторонними средствами без согласования. Обычные старые
подключения панель только наблюдает; их ключи и доступ защищены от изменения.
