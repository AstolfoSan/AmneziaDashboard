# AmneziaDashboard — переносимый установочный комплект 1.2.0

Это исходники нашей панели с группами, администраторами, выдачей гостевых `.vpn`,
статистикой, сроками доступа, паузой, лимитами трафика и журналом действий на русском и английском.
Не официальный продукт Amnezia. Цвета и оригинальный значок сохранены.

## Два варианта установки

| Режим | Куда подключается клиент | Где агент панели |
| --- | --- | --- |
| `direct` | Сразу к зарубежному VPN-серверу | На этом зарубежном сервере |
| `cascade` | К входному серверу, далее по существующему каскаду | На входном сервере |

Панель можно разместить на самом VPN-сервере или отдельно. Даже на одном сервере
веб-контейнер обращается к агенту по ограниченному SSH-ключу; Docker socket и
безусловный root-shell веб-приложению не выдаются. Адреса RU/Exit не зашиты.

Один экземпляр панели управляет одним VPN-входом. Это не единая мультисерверная
панель. Режим `cascade` сам не строит каскад и не меняет маршруты: сеть должна
быть настроена и проверена отдельно.

## Что нужно на новом сервере

- Linux, Docker Engine и Compose plugin, Python 3 с venv.
- Уже работающий совместимый **AmneziaWG 3.1** в Docker, интерфейс и `clientsTable`.
  Контейнер, интерфейс и внутренние пути настраиваются. Это не панель для произвольного
  WireGuard, AWG 1/2 или Xray и не установщик VPN-движка с нуля.
- Домен или IP с доверенным HTTPS-сертификатом и отдельно проверенным автопродлением.
- Доступ Codex по SSH к выбранным серверам для согласованной установки.

Документация Amnezia: https://docs.amnezia.org/ . Версию и совместимость нового
VPN-движка нужно проверить перед установкой, не обновляя существующий вслепую.

## Как передать задачу Codex

Распакуйте ZIP и откройте его папку в Codex. Скажите:

> Прочитай AGENTS.md и INSTALL_FOR_CODEX.md. Разверни эту AmneziaDashboard на
> указанном мной сервере в режиме direct (либо cascade). Сначала проверь сервер
> и сделай бэкапы, не ломай существующие VPN и конфиги. Адрес сервера и доступ
> я передам отдельно. Не публикуй ключи и пароли в чате.

В `examples/direct.json` и `examples/cascade.json` только учебные адреса из
документационного диапазона; замените их реальными параметрами. Скопируйте пример
в свой JSON и затем выполните **локальную генерацию**, которая не подключается к
серверу и ничего не устанавливает:

```text
python configure.py --config examples/my-deployment.json --output deployment-new
```

Генератор отказывается перезаписывать существующую папку. Результат — Compose,
настроенные исходники/надписи, nginx, настройки агента, ограниченный SSH-шаблон
и systemd-таймер. Полная последовательность — в `INSTALL_FOR_CODEX.md`.

## Состав и безопасность

- `app/` — актуальная бизнес-логика, интерфейс, агент и тесты.
- `portable_settings.py` внутри `app/` — проверка параметров и SSH-транспорт.
- `configure.py`, примеры и инструкция для Codex — подготовка новой установки.
- `run_checks.py`, `test_portable.py` — исходные регрессии и проверки direct/cascade.
- `MANIFEST.sha256.json` — хеши исходников для проверки целостности комплекта.

В архиве **нет** рабочих SSH-ключей, паролей, API-токенов, сертификатных ключей,
базы пользователей, выданных `.vpn` и реальных адресов наших серверов. Это новая
чистая установка, а не клон существующих клиентов. Действующая панель и VPN
при подготовке архива не изменялись.

Для сохранения существующих клиентов при реальной миграции нужен отдельный
секретный согласованный бэкап: БД/ключ панели, состояние/ключ агента и конфигурация
VPN должны соответствовать друг другу. Копировать только БД или только `.vpn`
недостаточно. Не смешивайте приватный бэкап с этим распространяемым ZIP.

Docker-образы и Python-зависимости загружаются при установке; это не офлайн-образ
всего сервера. Примеры фиксируют digest образов из проверенной сборки, не `latest`.
Перед будущим развёртыванием Codex должен проверить актуальность/архитектуру образов
и пакетов по официальным источникам. Без такого аудита не считать старые pins
бессрочно безопасными.

## Проверки

```text
python -m pip install -r app/requirements.txt
python run_checks.py --node /полный/путь/к/node
```

Тесты работают с временными данными и подставным VPN-движком, не с вашим сервером.
Они проверяют выдачу прямого `.vpn` с выбранным адресом/портом/DNS, сохранение
профиля при паузе, защиту старых клиентов, ограничения, генерацию обоих вариантов
и отсутствие секретов в комплекте. Реальный тест VPN на новом сервере обязателен:
автоматические тесты не доказывают проходимость UDP у конкретного провайдера.
