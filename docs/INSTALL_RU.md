# Установка AmneziaDashboard 1.0.0

[English](INSTALL_EN.md) · [Главная](../README_RU.md)

> [!WARNING]
> Мастер рассчитан только на **чистые VPS**, не на обновление действующего VPN.
> Полный direct/cascade прогон на чистых серверах ещё не принят. Начните с
> отдельно выделенных тестовых VPS, не с единственной рабочей установки.

## 1. Что подготовить

На каждом VPS: Ubuntu 24.04, systemd, публичный IPv4, root SSH и `/dev/net/tun`.
Минимум 1 ГБ RAM и 3 ГБ свободного диска; рекомендуется 2 ГБ / 5 ГБ для сборки
и бэкапов. Используйте amd64, если официальный AWG-образ не предоставляет
другую нужную архитектуру. Домашние роутеры и пробросы через NAT не поддержаны.

- **Прямой VPN:** один зарубежный VPS; панель и VPN находятся на нём.
- **Каскад:** два VPS; первый — вход (обычно RU), второй — зарубежный выход и панель.
- На вашем компьютере: Python 3.12+; интернет к GitHub, PyPI и официальным
  источникам Docker/Ubuntu/Amnezia/Let's Encrypt.
- Данные root по SSH: пароль или приватный ключ (не `.pub`). Убедитесь,
  что у вас есть резервный вход через консоль хостинга.

В firewall **хостинга** заранее разрешите необходимые порты:

| Узел | Порт по умолчанию | Назначение |
| --- | --- | --- |
| Каждый VPS | TCP 22 (или ваш SSH-порт) | Администрирование |
| VPN-вход | UDP 39265 | Клиенты AmneziaVPN |
| Сервер панели / зарубежный | TCP 10443 | HTTPS панели |
| Сервер панели / зарубежный | TCP 80 | HTTP-01 и продление TLS |
| Зарубежный, только каскад | TCP 443 **от адреса входного VPS** | Межсерверный TLS |

В прямом режиме VPN-вход и сервер панели — один VPS. Порты можно поменять
в мастере; они не должны быть заняты. TCP 80 оставьте доступным для продления.
Мастер не управляет кабинетом firewall вашего провайдера.

## 2. Скачать и проверить

Скачайте **AmneziaDashboard.zip** и **SHA256SUMS** с одного и того же
[релиза GitHub](https://github.com/AstolfoSan/AmneziaDashboard/releases).
Сначала убедитесь, что открыт именно репозиторий `AstolfoSan/AmneziaDashboard`.

Windows PowerShell:

```powershell
Get-FileHash .\AmneziaDashboard.zip -Algorithm SHA256
```

Linux:

```sh
sha256sum -c SHA256SUMS
```

На macOS: `shasum -a 256 AmneziaDashboard.zip` и сверка с SHA256SUMS.
При несовпадении хеша не запускайте файлы. Распакуйте архив целиком.
Далее откройте терминал в папке **AmneziaDashboard** с файлом VERSION.

## 3. Запустить пошаговый мастер

### Windows 10/11

Установите Python 3.12+ с официального сайта Python, затем:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r installer\requirements.txt
.\.venv\Scripts\python.exe installer\cli.py --self-test
.\.venv\Scripts\python.exe installer\cli.py
```

Активация venv и изменение ExecutionPolicy не нужны. Если релиз содержит
отдельный **AmneziaDashboardSetup.exe**, это необязательная сборка без установленного
Python: сначала проверьте её SHA-256. EXE не подписан сертификатом разработчика;
решение по предупреждению Windows принимает пользователь, не установщик.

### Linux / macOS

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r installer/requirements.txt
.venv/bin/python installer/cli.py --self-test
.venv/bin/python installer/cli.py
```

Linux может потребовать пакет venv для вашей версии Python. Мастер можно
запускать с отдельного компьютера: входить в shell самого VPS для запуска не нужно.
Интерактивный мастер пока на русском; [английская инструкция](INSTALL_EN.md)
содержит пояснения его пунктов.

## 4. Ответить на вопросы мастера

1. Выберите `1` — каскад или `2` — только зарубежный.
2. Укажите IP/SSH-порт зарубежного VPS, затем способ входа: пароль или файл ключа.
   Для каскада аналогично укажите входной VPS. Пароли вводятся скрыто и не
   передаются аргументами командной строки.
3. При необходимости измените порты.
4. Прочитайте условия Let's Encrypt и подтвердите их, если согласны.
   IP панели будет передан центру сертификации и появится в публичных CT-журналах.
5. Сверьте каждый SSH-отпечаток с консолью хостинга/ранее доверенным подключением.
   Если не совпал — отмените установку, не отключайте проверку.
6. Проверьте полный план и введите **УСТАНОВИТЬ**. До этого изменения не начинаются.

После аудита создаются и проверяются локальные before-бэкапы, устанавливаются
пакеты/Docker, новые VPN-компоненты, панель и ограниченный агент. Официальные
релизы проверяются заново и закрепляются по commit/digest. Готовность означает
прохождение обязательных проверок мастера, а не независимый аудит безопасности.

Мастер откажется перезаписывать существующие каталоги/контейнеры/VPN-интерфейсы
или освобождать чужие порты. Не удаляйте существующие службы для обхода отказа.

## 5. Первый вход и выдача профиля

В конце мастер покажет HTTPS-адрес панели, логин **owner** и папку с
**result-private.json**. В файле — первый пароль. Откройте его локально сами,
войдите в панель и смените пароль. Не отправляйте этот файл в issue или чат.

Создайте администратора (если нужен), группу и персональное подключение.
Получатель устанавливает официальный AmneziaVPN, скачивает `.vpn` либо
нажимает кнопку добавления. Для ручного способа: **Скопировать ключ → плюс
в AmneziaVPN → Вставить → подтвердить → Подключиться**. Одно устройство — один профиль.

Для приостановки клиента используйте паузу, срок или лимит трафика; не отзывайте
профиль, если планируете вернуть тот же доступ. Пауза кабинета администратора
сама по себе не отключает уже выданные VPN-конфиги.

## 6. Приватные файлы и восстановление

По умолчанию Windows сохраняет сессию в
`%LOCALAPPDATA%\AmneziaDashboardInstaller\sessions\<id>`, Linux/macOS —
`~/.local/share/AmneziaDashboardInstaller/sessions/<id>` (если LOCALAPPDATA не задан).
`--home` позволяет выбрать приватный каталог. Там находятся план, журнал этапов,
before/after архивы и первый пароль. На VPS также остаются root-only материалы
`/root/amnezia-dashboard-installer-<id>`.

Это **секретные данные**, не исходники: храните вне GitHub и публичного облака,
с ограниченными правами и отдельной защищённой копией. Before-архив — не полный
образ диска. Остановка/откат ограничены собственными компонентами и best-effort:
при потере SSH завершение очистки не гарантируется.

При ошибке не запускайте установщик снова поверх частичной установки. Сохраните
приватный журнал, проверьте точный этап и составьте план восстановления. Не
восстанавливайте старую базу поверх новых клиентов/счётчиков. Для остановки
используйте Ctrl+C и дождитесь завершения текущего этапа.

## 7. Следующие версии

Новые пакеты берите только из GitHub Releases, проверяйте версию и SHA256SUMS.
Для новой установки подходит свежий архив. Для действующей сначала нужны
проверенный бэкап, чтение changelog и совместимый план миграции. Универсальное
автоматическое обновление live-установки в 1.0.0 **не реализовано**.
